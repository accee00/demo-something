2. Deconstruction of Problem & Requirements

A. The Core Problem (The Gap):
  • Authoring Friction: Translating English user story acceptance criteria (AC) into reliable end-to-end tests (Playwright) requires significant manual engineering time.
  • Brittle Locators (Test Flakiness): Minor developer refactors (changing an ID from #btn-submit to #checkout-confirm, tweaking Tailwind CSS classes, or altering text from "Submit" to "Place Order") break tests even when the feature functions properly.
  • Maintenance Burden: QA engineers spend 30–50% of their sprints updating broken locators instead of testing new features.

4. Deep-Dive: Designing the Self-Healing Engine

[ Jira Issue / Mock Ticket ] → Extract Acceptance Criteria (Given / When / Then) ↓ [ AI Generator Agent (Gemini API) ] → Generate Playwright TypeScript Test Script ↓ [ Node.js Playwright Runner Worker ] → Execute Against Target Web Application ↓ +-------------------+-------------------+ | | | [ PASS ] [ TIMEOUT / LOCATOR ERROR ] [ HARD ASSERTION FAIL ] | | | | [ Capture Failure Telemetry ] → Log Genuine Product Bug | • Failed Selector & Code Location | • Current Page DOM & Accessibility Tree | • Page Viewport Screenshot | ↓ | [ SentinelQA Semantic Matcher ] | • Filter Interactive Elements (buttons, inputs, links) | • Multi-Attribute Semantic Similarity Scoring | ↓ | [ Babel AST Locator Rewriter ] → Patch selector in test script | ↓ | [ Re-Run Healed Test Suite ] | ↓ +--------> [ React Live Audit & Reporting Dashboard ] <--------+ • Healed Selector Diff Log (old → new) • Real-time Console Log Streaming (WebSocket) • Optional: Jira Result & Comment Pushback
• Distinguish Locator Drift vs True Regressions

Locator Drift: The element still exists and carries out the intended user action, but its ID, CSS classes, or inner text shifted during refactoring. → Self-Heal.
True Bug / Regression: The backend API returns 500, data is not saved, or the element was completely deleted without replacement. → Report Product Bug.

• Multi-Attribute Candidate Scoring

Calculate semantic and structural similarity across four key axes:
1. Tag & ARIA Role (25%): Confirms candidate matches interaction type (button, link, input).
2. Text Similarity (35%): Cosine similarity between expected label and current candidate text.
3. DOM Hierarchy (20%): Proximity to sibling fields, forms, and parent containers.
4. Accessibility Attributes (20%): Matches aria-label, name, and placeholders.

• Babel AST Locator Rewriter (Safe Deterministic Code Patching)

Instead of prompting an LLM to regenerate the entire script (which risks syntax errors, hallucinated test flows, or test logic drift), SentinelQA parses the test script with Babel AST (@babel/parser), traverses to the exact locator call node, replaces only the selector argument (e.g., page.locator('#submit-btn') → page.locator('button:has-text("Place Order")')), and regenerates clean code using @babel/generator.

5. Bonus Goals & Hackathon Differentiators (Page 21)

• Jira Two-Way Sync

Post execution results, failure traces, execution screenshots, and healed locator diffs directly back to the Jira ticket via Jira REST API as comments, updating status to "QA Verified".

• Flaky Test Detection (Monte Carlo)

Execute tests repeatedly (N = 5) under synthetic CPU throttling and simulated network jitter (3G) to differentiate asynchronous race conditions from deterministic locator failures.

• Visual Regression Checks

Integrate Pixelmatch to compare baseline screenshots with post-change screenshots, isolating cosmetic visual modifications from functional DOM breakages.

• Integrated Demo Sandbox App

Include a built-in React demo application with a prominent "Simulate Refactor" toggle that mutates IDs, classes, and labels in real time to demonstrate live self-healing in front of judges.

9. Hackathon Rules & Strict Compliance Checklist

[x] Safe Targets Only: Execute exclusively against our local demo app or open testing sites (e.g., SauceDemo). Zero probing of external commercial apps.
[x] Transparent Audit Logging: Every repaired locator logs exact timestamps, previous selector, healed selector, semantic confidence score, and rationale.
[x] Live System Execution: All test runs, failure interceptions, and DOM inspections execute live in real browsers with zero mock delays or hardcoded values.
[x] Secure Credential Protection: Strict environment isolation via .env for API tokens; zero plain-text secrets in repository files or client bundles.
Summary Recommendation: SentinelQA built on Node.js and React provides maximum developer velocity and flawless integration with Playwright. Using Babel AST for in-place locator substitution ensures safe, deterministic healing without code hallucinations, creating an unbeatable hackathon demo.
